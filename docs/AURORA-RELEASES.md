## AURORA 6

## Aurora 6 — shared artwork-backed application chrome

Aurora 6 extends Aurora 5's three theme resources with a **third, separate
app-side image atlas**: the editable `chrome-strip.png`. The original window
frames, taskbar and icon art remain unchanged. This phase targets native
application interiors; it does **not** yet replace the separate procedural
Start-menu background or every game-specific graphical element.

### Editing artwork

Edit these three **original, unpackaged PNGs** (one per theme) in Aseprite,
Krita, GIMP or another raster editor. They are never regenerated by `make`:

- `assets/ui/aurora/chrome-strip.png` — Aurora Blue
- `assets/ui/aurora/olive/chrome-strip.png` — Olive Green
- `assets/ui/aurora/midnight/chrome-strip.png` — Midnight

Keep each source at **192 × 64 pixels** with non-interlaced RGB/RGBA PNG
encoding. Each horizontal region is an independently resizable 9-slice:

| Vertical pixels | Runtime drawing | Source dimensions | 9-slice margins L/R/T/B |
| --- | --- | --- | --- |
| 0–25 | App header, 26 logical px | 192 × 26 | 9 / 9 / 7 / 7 |
| 28–45 | Status bar, 19 logical px | 192 × 18 | 7 / 7 / 4 / 4 |
| 46–63 | Toolbar (user-defined height) | 192 × 18 | 7 / 7 / 4 / 4 |

Rows 26–27 are unused padding. Side margins should be painted with repeatable
edge art, while the center should not contain text or distinctive shapes:
9-slice mapping stretches the center with nearest-neighbor sampling.

**Artwork:** Editable theme `chrome-strip.png` masters remain in the three
Aurora theme directories. Historical preview sheets have been removed.

### Applications updated

- **Notepad**: coherent header, image-backed Open/Save controls, white editing
  surface, status bar, and theme-change wakeups. Existing document buffer
  and persistence semantics remain unchanged.
- **Calculator**: artwork-backed key grid and display, proper 16/43-pixel
  chrome-offset correction for native click events, and a geometry regression
  test sharing the same rectangles as drawing.
- **Calendar**: themed navigation buttons, grid header/selection colors,
  proper mouse offset handling, and synchronized drawing/hit testing.
- **Paint**: themed header and palette panel, graphical Open/Save controls,
  and recoloring of native chrome on a theme change without losing drawing.
- **Terminal**: shared themed application bar while preserving its deliberate
  dark-console surface, theme change updates without discarding scrollback.
- **Clock / Monitor / About**: shared native shell bars, surfaces and status
  strips with automatic theme refresh.
- **Run / Settings / File Manager / WordPad**: existing Aurora widgets now
  automatically use the new chrome PNG for shared toolbars and supported bars.

Missing/invalid PNG resource: the individual component renders its prior
procedural fallback, instead of preventing the application from opening.

### Runtime contract and memory

`tools/pack_ui_atlases.py` creates each `*-chrome.oxua` using exactly the
same bounded OXUA v1 representation as the original widget/icon atlases.
`mkinitrd.py` places **all 12 theme resources** into the read-only OXRD boot
archive (3 themes × 1 window skin + 3 atlases). The shared native widget layer
loads a bounded per-process copy via file syscalls. No kernel PNG decoding,
privileged framebuffer mapping or dynamic relocations were added.

Apps newly using image-backed widgets now reserve **192 KiB writable native
memory** (rather than 32 KiB) to accommodate three atlases with 147,456
pixel bytes and state. The Ring 3 image remains freestanding, PIE and uses
only permitted general-purpose instructions. This is a temporary bounded
allocation policy, not an actual demand-paged graphics allocator.

### Verification

```
make kernel
make test-unit
make test-calculator-layout
make test-calculator-layout-sanitize
make test-aurora-themes
make test-ui-atlas
make smoke-shell   # Requires QEMU, a working Limine ISO build
```

Host tests check pack integrity, exact content, widget bounds, shared
calculator hit geometry, native image headers, and the real ELF-object .bss
budgets against RW mappings inside the built initrd. Live visual behavior,
scrolling and performance still need a QEMU/VirtualBox boot with each theme.

### Limitations and next work

The Start-menu main panel, some game-specific interfaces and older Ring 0
fallback windows remain procedural. This does **not** add downloadable fonts,
true font anti-aliasing, display DPI scaling or full persistence of appearance
settings across reboots. A next phase can add sprite-backed Start-menu panels,
shared menu/tooltips, and typography based on licensed redistributable fonts.

## AURORA 7

## Aurora 7 — artwork-backed Start menu

Aurora 7 retains the Aurora 6 Ring 3 shell and adds one OXUA atlas for each
appearance. The Start menu itself, header, hover/selected row, footer and
hovered desktop label plate now render from an **original editable PNG master**.
The older procedural elements remain the fallback when a resource cannot be
loaded. The kernel does not decode PNGs or gain graphics privileges.

### Where to edit

- `assets/ui/aurora/menu-atlas.png` — Aurora Blue
- `assets/ui/aurora/olive/menu-atlas.png` — Olive Green
- `assets/ui/aurora/midnight/menu-atlas.png` — Midnight

All **192 × 128 RGBA**, non-interlaced, 8-bit per channel PNG. Use a raster
editor to replace the art, retaining the regions below. Rebuilding automatically
converts each source into an OXUA resource; source PNGs are never overwritten.

| Region | Atlas X/Y/W/H | 9-slice L/R/T/B | Purpose |
| --- | --- | --- | --- |
| Main menu | 0 / 0 / 96 / 96 | 12/12/12/12 | 514 × 370 Start panel |
| Header | 96 / 0 / 96 / 28 | 9/9/8/6 | 510 × 47 header |
| Selected | 96 / 28 / 96 / 24 | 8/8/7/7 | 234 × 37 selected row |
| Hover | 96 / 52 / 96 / 24 | 8/8/7/7 | 234 × 37 pointer hover |
| Footer | 96 / 76 / 96 / 26 | 9/9/7/7 | 510 × 29 menu footer |
| Icon label | 96 / 104 / 96 / 24 | 9/9/7/7 | 95 × 29 desktop-hover chip |

**Keep central regions free from text and distinct motifs:** nine-slice scaling
stretches the center without distorting corners. Keep the outside edges
transparent where rounded corners are intended.

The editable `menu-atlas.png` files remain the source of truth; the
historical Aurora 7 contact-sheet image was removed during repository cleanup.

### Runtime and interaction behavior

- `apps/native/shell_menu_art.[ch]` validates and renders bounded RGB565+A8
  scanlines from the packed OXUA resource. Source bounds, destination clipping,
  thin/tiny widths and transparency are explicitly handled.
- `windowd` loads the atlas for its selected appearance. A missing or corrupt
  file activates the previous procedural menu; no hard crash or boot failure.
- Selection art is rendered *beneath* label text and the existing icon atlas.
  Mouse hit targets and menu action mapping are unchanged.
- Desktop names are horizontally centered, with a 1-pixel drop shadow. On hover,
  a translucent asset-backed label plate improves contrast over wallpapers.
- Selection changes from keyboard, pointer, or theme switching invalidate the
  appropriate cached shell raster layers. This avoids stale hover artwork.
- Nine-slice calculations and all sprite processing stay in Ring 3; this adds
  three immutable read-only initrd resources, **15 total per 3 themes**.

### Building and testing

```
make kernel
make test-unit
make test-shell-menu-art-sanitize
make test-aurora-themes
make test-ui-atlas
make smoke-shell        # needs QEMU, Limine, ISO build tools
```

`make test-sanitize` covers the broad sanitizer suite. It can take substantial
additional time and is a separate verification step. Live QEMU/VirtualBox
verification should cover opening Start, pointer hover, keyboard navigation,
changing all three themes, launch actions, wallpaper hover labels and fallback
with an intentionally missing menu atlas.

### Not covered in Aurora 7

This phase is **not** a complete desktop font engine. Text still uses the small
built-in glyph rasterizer, and some legacy Ring 0 interfaces remain procedural.
The artwork itself can be edited independently, but only a rebuilt ISO includes
new PNG edits (not hot-loading them). Appearance persistence across reboots
still depends on OpenXP persistent storage support.

## AURORA 8

## Aurora 8 — fonts and native toolbar controls

Aurora 8 introduces a **user-editable, immutable bitmap font atlas** and a
shared toolbar button skin for the three Aurora appearances. The Ring 3 shell
and Aurora's shared app controls use the same OXFT font resource. This doesn't
change the kernel's historical 5×7 emergency renderer: it remains available
when resources are missing or damaged.

### Edit the actual artwork

| File | Source dimensions | Use |
|---|---|---|
| `assets/ui/aurora/fonts/aurora-font.png` | 176×156 | 95 printable ASCII glyphs, regular rows 0–5 and bold rows 6–11 |
| `assets/ui/aurora/toolbar-atlas.png` | 192×64 | Aurora Blue toolbar and action states |
| `assets/ui/aurora/olive/toolbar-atlas.png` | 192×64 | Olive Green |
| `assets/ui/aurora/midnight/toolbar-atlas.png` | 192×64 | Midnight |

**Font layout:** 16 columns by six rows per style, each 11×13 pixels. Character
code 32 (space) starts at `(0,0)`; the next characters advance in ASCII order
through code 126. Bold starts at atlas `(0,78)`. Leave unused cell 95 empty.
Raster advances are derived from each character's nontransparent width and
recomputed automatically on build. A 4-pixel word space is built in.

**Toolbar atlas:** first 192×22 pixels = scalable toolbar background. Three
64×25 button states at `(0,23)`, `(64,23)`, `(128,23)` = normal, hovered,
pressed. The 192×15 bottom strip is reserved for artwork variations.
Each state uses a 6-pixel nine-slice border to preserve corners.

Regular and bold glyph rasters were initialized from the freely distributable
DejaVu Sans typeface. The source contains only **bitmap artwork**, not font
binaries. See `docs/FONT-LICENSE.txt` for the attribution and license notice.
Draw over the glyphs directly with your favorite raster editor; PNG edits are
never overwritten by the packer.

### Format and rendering

- `tools/pack_aurora_font.py` reads the PNG with the existing standard-library
  decoder and emits `build/skin/aurora-font.oxft` (27,662 bytes).
- `OXFT` starts with a 16-byte versioned header, 190 glyph advances, and
  27,456 bytes of alpha masks. Resource bounds and advances are validated
  before any font pointer is accepted.
- `apps/native/font_engine.h` is the small shared loader/metrics API.
- `windowd` uses the new proportional font for shell text, including desktop
  icons; the original shell glyph renderer is still the fallback.
- Native applications load once at launch. Headers and shared toolbar command labels use the bold style, while regular body controls use the normal style. Widget text is assembled in
  bounded 32×13 RGB565/alpha bitmap tiles and sent through the *existing*
  GUI bitmap syscall, **not a new privileged framebuffer API**.
- `toolbar-atlas.png` is compiled alongside existing Aurora sprites into
  three `OXUA` files. 9-slice makes buttons resizable while preserving edges.
- Run, Settings, File Manager, WordPad, Paint and Notepad use more consistent
  text/toolbars. Other applications share the general UI helpers automatically.
- Native application RW reservation rises from 192 KiB to 256 KiB to hold
  the new immutable bitmap caches; a boot-image-based regression test checks
  that every themed app retains memory headroom.

### Tests

```bash
make kernel
make test-unit
make test-font-engine-sanitize
make test-aurora-themes
make test-ui-atlas
make smoke-shell  # requires ISO tools, Limine and QEMU
```

### Current limitations

This is a **bitmap font engine**, not a vector/OpenType font renderer. The
initial glyph set is printable 7-bit ASCII; Cyrillic, Greek, international
scripts, kerning, font shaping, and arbitrary sizes require additional work.
Text editors and games still use the old fixed-width glyph draw path where
cursor positions, wrapping and gameplay grid geometry depend on 6-pixel
advances. Some older Ring 0 interfaces still use procedural graphics.

Full desktop interaction and font sharpness at different VM resolutions must
be inspected in QEMU/VirtualBox. Source-level checks alone can't certify
rendering smoothness or text legibility.

## AURORA 9

## Aurora 9 — Clipped typography and toolbar selection

This release adds a bounded pixel-aware label layout layer to the existing
Aurora `OXFT` font system. It does **not** replace the monospaced document
font in Notepad/WordPad, whose layout and caret coordinates are based on
six-pixel character cells.

### Changes

- `oxp_font_fit`: pixel-accurate fit using actual glyph advances. The helper
  returns the number of source characters, width, and whether three dots
  should be rendered. It limits all text reads to a caller-provided cap.
- `oxp_ui_bitmap_text`: clips every glyph to the **control rectangle** as well
  as the client canvas, vertically and horizontally. Uses a 92-character cap
  and renders the `...` suffix from the real font atlas when needed.
- Fallback six-pixel labels receive their own basic ellipsis treatment.
- File Manager row names, location/path and status messages use the same
  proportional sizing and clipping instead of fixed `6px * characters`
  assumptions. Context menu text is consistent with the shared font.
- WordPad status bar uses the themed shared status widget; Bold and 200% zoom
  buttons now show selected/pressed artwork when enabled.
- All prior Aurora 8 artwork and three theme packs remain intact.

### Artist notes

This is a rendering/code refinement. Existing editable PNG sprite masters are
unchanged, not procedurally replaced:

- `assets/ui/aurora/fonts/aurora-font.png`
- `assets/ui/aurora/toolbar-atlas.png`
- `assets/ui/aurora/olive/toolbar-atlas.png`
- `assets/ui/aurora/midnight/toolbar-atlas.png`

The updated-files and full-source ZIPs both include **all** artwork PNGs to
avoid missing images after extraction. See `AURORA-RELEASES.md#aurora-8` for sprite atlas
coordinates, raster format and font credit.

### Checks

```sh
make kernel
make test-unit
make test-font-fit-sanitize
make test-font-engine-sanitize
make test-native-widgets-sanitize
make test-shell-raster-sanitize
```

`test-font-fit` is part of `test-unit`; it exercises narrow viewports, genuine
proportional widths, cap-based reads, and ellipsis placement. VM boot and visual
behavior should still be verified in QEMU or VirtualBox.

### Remaining limitations

The shell/event ABI currently provides click events, not continuous pointer
movement for hover transitions. The theme atlas contains hover sprites, but
true pointer-over UI feedback requires a separate event-protocol update. Full
Unicode text shaping and document-level proportional editing are not included.

## AURORA 10

## Aurora 10 — Shell interaction and redraw polish

This release refines the Aurora 9 Ring 3 desktop, not the Ring 0 fallback.
Artwork remains the editable Blue, Olive and Midnight Aurora PNG pack.

### Interactive changes

- The trusted shell input bridge now forwards pointer movement to `windowd`
  **without consuming the app's original mouse movement**. Adjacent move
  events are coalesced so a busy pointer cannot fill the 64-event queue.
- Desktop shortcuts, the Start button, Start menu rows and taskbar buttons
  are activated on **release over the original pressed target**. Moving off
  the target and releasing cancels activation; clicking outside an open Start
  menu dismisses it instead of triggering an app underneath.
- Hover and press states are rendered for the Start button and taskbar. Start
  has a short, bounded two-step glow transition and does not run an animation
  when the cursor is idle. Existing menu selection/hover sprites are driven
  by actual mouse movement.
- Native window caption-button hover now receives ordinary pointer movement
  and keeps its pressed state through drag events. It ignores captions covered
  by a higher legacy window. Application content input stays with the app.
- Start menu keyboard navigation now includes Tab, Shift+Tab, Home and End,
  alongside the existing arrows, Enter, Escape and Win/Ctrl+Escape shortcuts.
  Keyboard selection clears any stale mouse hover highlight.
- The shell invalidates **only the raster layer affected by a hover**. Move
  events that do not change any drawing commands or dirty layers skip the
  shell-frame publish syscall altogether. Window-order metadata changes
  still publish even when raster pixels remain the same.

### Implementation / safety

- No new privileged graphics privileges or syscall ABI changes.
- The compositor keeps the previous frame during application resizing.
- Input remains isolated from application-owned client surfaces.
- The event queue only coalesces consecutive movement events, never keys,
  button transitions or releases.
- The last known shell raster is preserved if a new upload fails.
- All Aurora 9 source and editable PNG assets remain present in the release.

### Tests

```sh
make kernel
make test-shell-bridge
make test-shell-bridge-sanitize
make test-shell-interaction
make test-shell-interaction-sanitize
make test-window-protocol test-desktop
make test-unit
make iso smoke-shell
```

### Known limitations

- Regular **native application widgets** still use their older click-event
  interface. Aurora 10 improves shell controls and native caption hover; a
  follow-on native pointer protocol is needed for hover/press/release states
  in every application toolbar and button.
- It is still necessary to verify the full visual behavior in QEMU or
  VirtualBox; host-side checks alone do not establish visual correctness.
- The full `make test-unit` target reached its syscall test build but was
  interrupted by the test execution time limit in this environment.
- This phase uses existing artwork; it does not redraw PNG assets.

## AURORA 11

## OpenXP Aurora 11 — Native widget pointer events

This phase completes the **opt-in native pointer event path** for the existing
Aurora shared controls without breaking native clients using the original
single-click ABI.

### What changed

- Syscall **35** enables pointer delivery for the calling process's already-open
  native window. The kernel never accepts a caller-provided PID or window slot.
- New native pointer event kinds are `0x20000000` (MOVE), `0x10000000`
  (DOWN), `0x08000000` (UP), and `0x10008` (LEAVE). For MOVE/DOWN/UP,
  `(event >> 10) & 1023` is X and `event & 1023` is Y. Coordinates retain
  the legacy frame offsets of **16 px X / 43 px Y**; 1023,1023 on a captured
  event denotes outside the client and cancels activation.
- Input is delivered to the topmost eligible native window. A press is
  captured until release; another window does not steal the release.
  Process recycling is checked using the owner's PID.
- Consecutive MOVE events coalesce. A full queue drops new motion rather
  than displacing key or release events. A release can evict old motion.
- `apps/native/ui_pointer.h` provides a bounded per-process gesture state
  machine. It recognizes enter/leave, hover, arm, press, cancel, and release.
- `ui_widgets.h` rebuilds a bounded 64-element hit-test registry as apps
  render shared buttons, toolbar buttons, tabs, checkboxes, scrollbars, and
  menu entries. Hover/pressed/focus states now affect their native drawing.
- Existing client action code receives the familiar `OXP_CLICK` encoding,
  synthesized **only on valid release**. Click-to-position in document/canvas
  regions is preserved. A release outside or over a different control cancels.
- Tab and Shift+Tab move keyboard focus among registered controls. Enter
  activates a focused control. Legacy keyboard events remain unchanged when
  no native widget has focus.
- The shared input behavior applies to all native apps that initialize Aurora
  widgets and use `oxp_ui_wait_theme()` (including Calculator, Calendar,
  Notepad, WordPad, Paint, File Manager, Settings and Run). Clients with an
  older event loop are not opted in.
- File Manager context-menu entries now use theme-aware hover highlights.

### Limitations and next engineering work

This is a widget interaction protocol, **not** complete native pointer API
coverage for every application feature. Existing Paint still paints discrete
clicks rather than brush-drag strokes; document selection and custom slider
thumb-dragging need dedicated continuous-gesture handlers. Keyboard traversal
works for the controls registered by shared Aurora widgets; older custom
controls keep their existing shortcuts. The legacy compositor remains a
fallback rather than using Aurora sprites.

### Verification

Run `make -j4 kernel`, `make test-unit`,
`make test-native-pointer-sanitize`, and `make test-desktop`. For VM verification,
run `make iso && make smoke-shell`, then test hover/release, moving outside
buttons, Tab/Shift+Tab, File Manager context menus, theme switching and
resizing. VM rendering and interactive pointer behavior are not automatically
proven by host-side tests.

All existing PNG masters under `assets/ui/aurora/` remain editable in the
existing three-theme artwork packs; this phase adds behavior, not new art.

## AURORA 12

## OpenXP Aurora 12 — Advanced Input & Editing

Aurora 12 builds on the Aurora 11 captured native pointer-event ABI. No new
kernel syscall, framebuffer privilege, or on-disk artwork format is required.

### Features

- **Paint** draws an uninterrupted brush stroke while the primary mouse
  button is held. Integer Bresenham interpolation fills gaps between mouse
  samples, stays inside the 64×40 drawing grid, and updates changed cells
  directly rather than redrawing the whole canvas on each movement.
- **WordPad** highlights the dragged text range, moves the caret with the
  pointer, supports selecting across wrapped lines, and replaces or deletes
  selected text when typing or pressing Backspace. It supports drag scrolling
  by grabbing its thumb, plus track clicking and the existing arrow controls.
- **Notepad** now has a movable caret, wrapped-text selection, and a small
  vertical scrollbar in addition to its RAM-backed Open/Save operations.
  Typing or Backspace replaces/deletes a selected range rather than
  exclusively appending at the end of the document.
- **File Manager** supports draggable list scrollbar thumbs without changing
  the current file selection. Long gestures do not trigger file opening.
- **Shared gesture API** (`advanced_input.h`) decodes the bounded, decoration-
  relative pointer coordinates and provides reusable rectangle, press/release,
  and thumb-position math. `ui_widgets.h` adds `oxp_ui_wait_gesture()`, an
  opt-in gesture stream; applications not using it retain release-click events.
  Idle pointer movement is filtered to avoid busy redraws.

The `OXP_POINTER_MOVE/DOWN/UP` events are already delivered by Aurora 11's
captured input path. Release sentinels outside the client are handled as
non-clicks. Changing the native window size cancels any active local drag.

### Build and regression tests

```sh
make -j4 kernel
make test-unit
make test-advanced-input-sanitize
make test-native-pointer-sanitize
make test-native-widgets-sanitize
make test-native-text-layout-sanitize
make test-native-scroll-sanitize
make test-desktop-sanitize
```

### VM check before release

Build the ISO, run `make smoke-shell`, and manually check drag-and-release in
Paint, Notepad, WordPad, and File Manager at small, maximized, and resized
window dimensions, plus press-drag-release outside the window and change of
Blue/Olive/Midnight themes during editing. Also test keyboard access to Save
and Open, document insertion at the caret, and actual saved document contents.
The host tests verify the math and the build, not what a running VM draws.

### Known limits

- Paint still uses the existing bounded 64×40 indexed canvas; drag movement
  does not enlarge the document resolution.
- Native editors are still ASCII-only and RAM-backed. No clipboard,
  multi-level undo, or persistent on-disk user documents are added here.
- Scrollbar dragging follows the real pointer within the client; the kernel
  currently reports an outside-window sentinel rather than an off-window
  position, so dragging outside clamps to the last in-client position.
- Interactive QEMU/VirtualBox testing is required to validate real rendering
  and frame-rate behavior. The build container does not include QEMU/Xorriso.
- Aurora's existing editable PNG assets are unchanged, but retained in the
  complete-source, updated-files, and artwork-only packages.

## AURORA 13

## Aurora 13 — desktop productivity and editing

Based on Aurora 12. This update adds a shared, volatile text clipboard,
bounded Undo/Redo, enhanced keyboard navigation, and theme-aware editor actions.

### Changes

- `kernel/gui/editor_keycodes.h` defines native editing key event IDs. The
  kernel's focused-window keyboard router translates Ctrl+A/C/X/V/Z/Y,
  Ctrl+Shift+Z, Shift+Arrow, Shift+Home/End, Home/End, Delete and
  Ctrl+Home/End into distinct, non-ASCII native events. Existing Ctrl+S/O,
  Alt+Tab, Win shortcuts and Ctrl+Esc remain with the desktop policy.
- `kernel/user/clipboard.h` plus syscalls 36 and 37 implement a single shared
  960-byte, volatile clipboard. The kernel validates and copies *all* user
  memory; the source cannot pass pointers directly into another process.
  Invalid pointers/capacities fail without modifying clipboard data.
- `apps/native/edit_session.h` offers bounded selection replacement, copy,
  cut, paste, line/document navigation and a 12-snapshot document history.
  Consecutive typing is grouped. Branching after Undo discards old Redo.
- Notepad and WordPad use these shared operations. At large window widths,
  they also expose five themed toolbar actions (Undo/Redo/Cut/Copy/Paste).
  Compact windows keep keyboard shortcuts.
- Paint has an eight-frame bounded stroke history; a stroke becomes one step
  on pointer release, and a new stroke after Undo discards Redo.
- Tests now check complete clipboard syscall access control, native keyboard
  delivery, text editing and history, paste overflow, and paint undo.
  The VFS test increases its outdated executable buffer from 16 to 32 KiB.

### Key bindings

| Keys | Effect |
|------|--------|
| Ctrl+C, Ctrl+X, Ctrl+V | Copy, Cut, Paste selected text |
| Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z | Undo, Redo, Redo |
| Ctrl+A | Select whole document |
| Left/Right/Up/Down | Move caret by character / wrapped visual line |
| Shift + arrows | Extend selection |
| Home/End | Move to current visual line start/end |
| Shift+Home/End | Extend selection to visual line boundary |
| Ctrl+Home/End | Move to document start/end |
| Ctrl+Shift+Home/End | Select to document start/end |
| Delete, Backspace | Delete forward / backward |

### Design limits

- Clipboard is plain text (ASCII plus line breaks) and has **no persistence**
  across reboots. It is available to all local native apps: this is a simple
  single-user desktop, not a privacy-isolated clipboard permission system.
- Editors are still ASCII-only and limited to a 960-byte buffer (959 bytes of
  text plus terminator); multi-megabyte files, Unicode, styled rich text,
  per-character formatting and system-wide keyboard layout switching are not
  implemented.
- Undo is **bounded**: up to 11 prior text snapshots and 7 prior Paint strokes;
  it isn't a disk-based journal. File Open/New resets the editing history.
- Shared clipboard is implemented as a small kernel service for this phase;
  moving clipboard ownership to a Ring 3 service remains future hardening.
- New editing toolbars appear only in large Notepad/WordPad windows to avoid
  overlapping existing compact layouts.
- Older Ring 0 legacy editor fallbacks are not migrated to the native clipboard.
- Manual graphical QEMU/VirtualBox verification is still required, especially
  release-outside, dragging, the large-window toolbar, and cross-app paste.

### Build/verify

```sh
make -j4 kernel
make -j4 test-unit
make -j4 test-sanitize
## On a runner with Limine, xorriso and QEMU:
make iso
make smoke-shell
```

#### Manual VM acceptance checklist

1. Open native Notepad; type two words, Shift+Home, Ctrl+C.
2. Open WordPad; Ctrl+V, Ctrl+Z, Ctrl+Y, then cut/paste the selected text.
3. Select across a wrapped line with Shift+Down and test Home/End.
4. Move the cursor after Undo and type: the stale Redo must disappear.
5. Paint multiple strokes; Undo/Redo and make a new stroke after Undo.
6. Maximize both editors, click all five themed edit toolbar controls.
7. Switch Blue, Olive and Midnight with both editors open and resize them.

## AURORA 14

## OpenXP Aurora 14 — File Management & Document Workflows

Base: Aurora 13. No new kernel filesystem or executable permissions.

### Desktop and File Manager

- Single click selects an item; a second click within 35 PIT ticks on the **same path** opens it. Existing Enter / Open context command works as before.
- Associations: `.txt`, `.log`, `.cfg`, `.ini` -> Notepad; `.md` -> WordPad; `.oxp` -> Paint. `.bmp` continues to use File Manager's **Set Wallpaper** behavior. `.exe` aliases continue to use the kernel's explicit native-app allowlist. Renaming a file to `.exe` does **not** grant execution rights.
- Open selected documents using per-application mailboxes (`home/open-notepad.cfg`, `home/open-wordpad.cfg`, `home/open-paint.cfg`) that are consumed at app launch. This reduces cross-editor races; it does not provide atomic process arguments and two simultaneous opens of the same target app may still supersede a mailbox.
- Ctrl+C / Ctrl+X / Ctrl+V: tagged binary file clipboard; context menu exposes Open, Copy, Cut, Paste, Rename, Delete, Properties. The existing system-wide clipboard is shared with text editors: copying text replaces a pending file clipboard entry and vice versa. Copying a file does **not** load the file content into the text clipboard.
- Paste targets Home / My Documents (aliases of one bounded RAMFS). Read-only files can be **copied** into writable Home but not moved or deleted. Directory trees cannot be copied; no real writable folder structure yet.
- File copies never overwrite existing files. For example `notes.txt` -> `notes.copy.txt` -> `notes.copy2.txt` to preserve association. A cut from Home pasted back into its Home/My Documents view is a no-op, not an implicit rename.

### Native editors

The shared `file_picker.h` provides a modal Open/Save As panel for Notepad, WordPad and Paint:

- Browse writable Home and bundled Docs when opening. Save As always targets writable Home.
- Select a file row, then Open; type a filename for Save As, or choose an existing one. Enter confirms, Esc cancels, Ctrl+A clears the name field in Save As, Backspace edits it.
- Validate filename and extension before opening or saving. No traversal or non-ASCII names. Overwriting an existing Home file requires a second confirmation.
- The Save button continues saving to the current document; Save As creates/selects another file name. Notepad retains its original HOME buffer when no file path is selected. Opening read-only Docs and saving afterward creates a writable Home copy.
- Document and paint buffers remain bounded (see Aurora 13). Unsupported/too-large files are rejected by the existing VFS read API.

### Limits / VM checks

- `home/` files live in a bounded RAMFS (47-byte path limit, max file size defined in `kernel/fs/ramfs.h`); larger files are not editable in this version.
- This is an in-app picker, not yet a separate reusable OS-level file-dialog service. It is shared source code among the three editors.
- Modal controls may be tight in a very small window: maximize the editor if needed.
- Binary file clipboard is in memory and does not persist across reboot; no Unicode paths, drag-and-drop file transfer or persistent file associations UI.
- A VM test is still required for mouse interaction, redraw accuracy, and simultaneous document launches.

### Testing

`make kernel` builds the native apps and runs the Ring 3 ISA check.
`make test-aurora14` covers associations, path/collision handling, tagged clipboard validation, double-click timing, picker filename validation, and Escape/selection editing.
`make test-aurora14-sanitize` runs the dedicated test with AddressSanitizer and UndefinedBehaviorSanitizer.
`make test-unit` and `make test-sanitize` include Aurora 14 tests along with the pre-existing suite.

No new theme PNGs were required: the existing 35 original editable PNGs remain in `assets/ui/aurora/`.

## AURORA 15

## Aurora 15 — Filesystem & Application Integration

### Document launch arguments

Aurora 14 used global HOME mailbox files (`home/open-*.cfg`) to pass a
filename to the next editor. That was susceptible to overwrites when two
launches targeting the same editor were queued. Aurora 15 adds an atomic
single-slot `app_launch_request_t` holding an allowlisted executable and
an optional path (48 and 96-byte NUL-terminated fields). The boot controller
binds that path to the newly created process ID *before* it runs.

New Ring 3 calls:

- `OXP_SYS_APP_LAUNCH_ARG` (38): takes a bounded struct, validates both
  fields and the same executable allowlist used by the original syscall.
  Paths may not traverse `.` or `..` segments or contain control characters.
  One pending launch request is allowed; callers can retry after EAGAIN.
- `OXP_SYS_APP_GET_ARG` (39): copies the current process's argument plus
  trailing NUL to its own writable memory, or reports the absence of an
  argument with zero. It never exposes another process's argument.

Explorer now uses `oxp_launch_document()` rather than writing the old mailbox.
Notepad, WordPad and Paint read the argument at startup; the mailbox parser is
retained only to support older callers. This is a single path argument rather
than general POSIX `argc/argv` or an unrestricted executable loader.

### Centralized file picker

All three Ring 3 editors continue to use `apps/native/file_picker.h`. The
shared picker now supports editing the filename in **Open** as well as **Save
As**, Tab/Shift+Tab between the list and filename field, selecting a listed
file on click and opening it on double click. Save As still prompts before
replacing an existing file; path and extension restrictions remain.

### Explorer file drop

File Manager now supports dragging a visible, ordinary file onto the
**DOCUMENTS** sidebar entry to copy it into writable `HOME`. Files originating
in the HOME store already belong to Documents and are not duplicated by this
gesture. Copying preserves the original and uses `.copy`, `.copy2`, etc. if
necessary; system files cannot be moved or deleted. There is selection/highlight
feedback over Documents. The operation does not replace the shared text
clipboard. Drops onto arbitrary windows, other folders, or the desktop and
folder trees remain unsupported.

### Persistent storage status and flush request

For builds compiled with `OPENXP_ENABLE_EXPERIMENTAL_IDE_STORAGE` **only**:

- Syscall 40 reads capability, dirty, pending and last-error flags.
- File Manager key **F** queues a disk save. The syscall does not perform
  disk I/O. The boot-controller thread performs journal commits with a
  minimum retry interval, avoiding write storms or a syscall doing slow I/O.
- Periodic commits use elapsed PIT ticks rather than equality with
  `now % 200`, which could skip attempts if the main loop was busy.
- The existing CRC-checked dual-slot journal is retained. No disk is
  formatted or mounted automatically unless its dedicated OpenXP header
  matches exactly.

The **default ISO remains RAM-only**. This is not persistent without building
and booting `make iso-storage` with a dedicated, disposable formatted IDE data
disk. No disk safety or VirtualBox data-integrity certification is implied.

### Testing

`make kernel` and `make kernel-storage` build. Focused Aurora 14/15,
application-launch, process isolation, syscall, and journal tests pass both
normally and under ASan/UBSan. The Ring 3 PIC/ISA audits pass.
Actual screen-level mouse gestures, full CI completion and QEMU/VirtualBox
boot remain unverified in the supplied development environment.

## AURORA 16

## OpenXP Aurora 16 — Desktop Filesystem & Window Integration

Aurora 16 extends the existing Aurora 15 Ring 3 desktop. All original Blue,
Olive, and Midnight PNG artwork is preserved. This is an experimental OS,
not a conventional POSIX filesystem or a Windows-compatible environment.

### Writable folders

The VFS now supports creation and removal of empty folders underneath HOME and
its My Documents aliases. Folder records use zero-byte RAMFS entries of the
form `home/projects/.oxpdir`. They are internal metadata: VFS users see a
`home/projects` directory, not the marker file. Existing disk snapshots can
store these ordinary RAMFS records without changing the snapshot ABI.

New native file syscalls (same `app_file_request_t` buffer):

| Operation | Value | Result |
| --- | --- | --- |
| `APP_FS_MKDIR` | 9 | Create empty writable directory (`req.path`) |
| `APP_FS_RMDIR` | 10 | Delete empty writable directory only |
| `APP_FS_STAT` | 11 | Fill `req.index` = VFS kind, `req.size` = length; returns 0 |

System folders remain immutable. Nested folders and files share the **12 RAMFS
record** and **48-byte backing name** limits. Filenames are ASCII and validated.
Marker records count against the limit. All data is volatile without the
separate experimental storage build and a dedicated formatted IDE disk.

### File Manager

- Navigate into created directories with double-click and return with Back/Up.
- Create folders via **N** or **+ NEW FOLDER** in a sufficiently wide window.
- Select an item and use **P** or right-click > **PROPERTIES** for item kind,
  byte length and read-only/writable status.
- **Delete** removes selected files or **empty** HOME folders; never system
  folders. Rename continues to apply to ordinary writable files, not folders.
- Copy/paste resolves unique names in the **current** writable folder.
- Drag files within File Manager onto writable folder rows or Documents to
  copy them; neither operation replaces the text clipboard.

### Cross-window file drag

Short, safe document paths (51 bytes or fewer) can be offered by File Manager
using `wm_drag_packet_t`, a separate 64-byte IPC packet. The Ring 3 window
manager validates the path's VFS kind, checks the supported document types,
and observes the global pointer release without consuming the source client
mouse event. When a file is dropped over an existing Notepad, WordPad or
Paint window and the type matches, OpenXP **launches a new editor process
with the file path**. The current editor's contents remain untouched.

This is **not yet a general drag-and-drop framework**: no arbitrary payloads,
no cross-window folder moves, no injection into an already-open editor, and
no support for long paths. The number of simultaneously open native clients
remains bounded. End-to-end UI behavior has not been validated in QEMU/VirtualBox.

### Desktop icon visibility

Display Properties has a **ICONS: SHOW/HIDE** button (or **I** shortcut). It
requests `WM_DESKTOP` on the Ring 3 window manager and stores a one-byte flag
in `home/desktop.cfg`. The window manager restores this setting at startup.
It affects Ring 3 desktop shortcuts, not the older Ring 0 fallback desktop.
A persisted selection only survives reboot when the experimental storage
system is configured and the snapshot is successfully committed.

### Terminal

`MKDIR path`, `RMDIR path`, `STAT path` are available. Directory listing is
corrected to handle Terminal's trailing-slash current path representation.

### Safety and verification

Compiled with the freestanding x86-64 Clang/LLD toolchain. The complete host
unit suite, VFS/shell routing regressions, targeted ASan/UBSan and the Ring 3
PIC/ISA checks pass. No ISO, physical hardware, VirtualBox or QEMU run has
been performed here. Always run GitHub Actions and test inside a disposable
virtual machine before distributing a release.

## AURORA 17

## Aurora 17 — Filesystem expansion & persistent desktop

### Shipped source changes

1. **48 RAMFS slots** instead of 12. Each slot permits up to 16 KiB of
   content and a 47-character relative path. Directory markers consume slots.
   The maximum theoretical content capacity is 768 KiB; this is **not** an
   unbounded or pageable disk filesystem.
2. **Atomic folder tree rename/move**: under HOME, renaming a directory now
   renames its `.oxpdir` record and its descendants together, after checking
   every target path for length, collisions and unsafe nesting. A failure
   changes no records. System folders cannot be renamed.
3. **File Manager** lets users rename nonempty HOME folders. Cut/Paste can move
   writable folders into another writable directory; copying folder trees is
   deliberately unavailable. Existing file clipboard operations remain.
4. **OXPDISK2 storage layout**: new, explicitly created 2 MiB images reserve
   two 1,700-sector CRC32 journal slots. The commit header is written last.
   Legacy `OXPDISK1` is detected and continues with its previous 400-sector
   slots, rather than silently being reformatted or interpreted as v2.
5. Existing desktop preferences in `home/desktop.cfg`, `home/appearance.cfg`, and
   `home/wallpaper.cfg` are included in the normal snapshot automatically when
   the experimental storage-enabled build is used and a dedicated disk mounts.

### How to run

```sh
make kernel
make test-aurora17
make test-aurora17-sanitize
make test-unit
## The following is experimental, for a *dedicated disposable virtual disk*:
make run-storage
```

`make run-storage` only creates its data image when missing, and it never
migrates or overwrites an existing disk. If an old OXPDISK1 image is attached,
its original capacity still applies. Create an entirely new image when larger
persistent storage is needed; there is no data migration feature yet.

### Verification / limitations

Host tests cover 48 full 16 KiB files, preference restoration, per-version
journal geometry, interrupted commits, CRC, transactional folder moves and
failure rollback. Real boot/pointer/IDE persistence must be validated in a VM.
The default boot is volatile, snapshot writes are synchronous, and filenames
remain ASCII with 47-byte relative-path limits. There are no arbitrary
removable volumes, recursive delete, file handles, or background disk queues.
